# Ipon Challenge — Low-Level Requirements (MVP Prioritized)

## Project Information

**Project Name:** Ipon Challenge
**Type:** Student Personal Finance & Budget Tracker
**Developer:** Vic Andrew A. Dizon
**Architecture:** Fullstack Web Application
**Tech Stack:**

* Frontend: React + TypeScript + Tailwind CSS
* Backend: Java Spring Boot
* Database: PostgreSQL

---

# 1. MVP DEVELOPMENT PRIORITY

## Phase 1 — Core MVP (Must Be Working First)

These features are required for a usable working system.

### Authentication

Priority: Critical

Features:

* User Registration
* User Login
* JWT Authentication
* Password Hashing
* User Session Handling

Reason:
The application cannot function without user accounts.

---

### User Allowance Setup

Priority: Critical

Features:

* Set monthly allowance
* Set allowance schedule:

  * Weekly
  * Biweekly
  * Monthly
* Update allowance information

Reason:
Allowance is the foundation of budgeting calculations.

---

### Expense Tracking

Priority: Critical

Features:

* Add expense
* Edit expense
* Delete expense
* Expense categories
* Transaction history
* Notes field
* Date tracking

Reason:
Expense tracking is the core feature of the system.

---

### Budget Management

Priority: Critical

Features:

* Create category budgets
* Track remaining budget
* Auto-update budget after expenses
* Monthly spending summary

Reason:
Budgeting is the primary purpose of the application.

---

### Dashboard

Priority: Critical

Features:

* Current balance
* Remaining allowance
* Spending summary
* Budget overview
* Recent transactions
* Daily safe spending amount

Reason:
Dashboard is the main user interaction screen.

---

### Allowance Runway Predictor

Priority: High

Features:

* Calculate estimated days remaining
* Predict if allowance lasts until next schedule
* Generate warning messages

Example:

* “Your allowance may run out in 3 days.”

Reason:
Main unique selling feature of the project.

## Business Logic Requirements

### Expense Logic

System must:

* Deduct expense from remaining allowance
* Update category budget
* Update analytics automatically

---

### Allowance Predictor Logic

System calculates:

```txt
remaining_balance / average_daily_spending
```

Then compares:

```txt
predicted_days_remaining
vs
days_until_next_allowance
```

Result:

* Safe
* Warning
* Critical

# 8. DESIGN PATTERN IMPLEMENTATION

Purpose:

```txt

```

Purpose:

Strategies:

* NormalBudgetStrategy

## Observer Pattern

Purpose:
Notification system.

Observers:

* BudgetWarningObserver

# 13. MOST IMPORTANT ENGINEERING PRIORITY

The MVP should prioritize:

1. Stability
2. Simplicity
3. Working core features
4. Clean architecture
5. Demonstration of OOP concepts

Avoid:

* Overengineering
* Complex microservices
* Too many features early
* Premature optimization
