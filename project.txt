1. AUTHENTICATION MODULE (User System)
1.1 Registration API
Endpoint

POST /api/auth/register

Request Body
{
  "fullName": "string",
  "school": "string",
  "email": "string",
  "password": "string",
  "monthlyAllowance": number,
  "allowanceSchedule": "WEEKLY | BIWEEKLY | MONTHLY"
}
Rules
Email must be unique (DB constraint)
Password must be ≥ 8 characters
Password must be hashed (BCrypt)
Monthly allowance must be > 0
Schedule must match enum
1.2 Login API

POST /api/auth/login

Response
{
  "token": "JWT",
  "userId": "uuid"
}
Rules
Invalid credentials → 401 error
Token expires in 24 hours

2. ALLOWANCE ENGINE (CORE FINANCE LOGIC)
2.1 Allowance Calculation Rules
Monthly → Weekly Conversion
weeklyAllowance = monthlyAllowance / 4
Biweekly
biweeklyAllowance = monthlyAllowance / 2
2.2 Daily Safe Spending Formula
remainingBalance / remainingDays
Rule
If remainingDays = 0 → safe spending = 0
2.3 Allowance Reset Logic
Weekly → every 7 days
Biweekly → every 14 days
Monthly → every 30 days (simplified MVP rule)
2.4 Backend Service
class AllowanceService {
  BigDecimal calculateRemainingBalance(User user);
  BigDecimal calculateDailySafeSpend(User user);
  LocalDate getNextAllowanceDate(User user);
}

5. DASHBOARD ENGINE (CORE UI LOGIC)
5.1 API

GET /api/dashboard

5.2 Response Structure
{
  "balance": 5000,
  "dailySafeSpend": 250,
  "nextAllowanceDate": "2026-05-28",
  "runwayDays": 6,
  "runwayMessage": "You can last 6 days at current spending"
}
5.3 Runway Logic (MVP)
runwayDays = balance / averageDailyExpense
Rules
If no expenses → assume safe
If averageDailyExpense = 0 → infinite runway
5.4 Runway Messages
≥ 7 days → “Healthy spending”
4–6 days → “Warning”
≤ 3 days → “Critical”
